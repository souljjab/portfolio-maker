# 리서치 요약 (설계 근거)

원본은 두 개의 심층 리서치 PDF. 구현에 직접 쓰이는 원칙만 추림.

## 문제 정의
사용자는 취향이 없는 게 아니라 이미 가진 취향을 디자인 언어로 번역하지 못한다. 서비스는 "자기표현 번역기" / "AI Art Director".
흐름 원칙: 말하게 → 보여준다 → 고르게 → 왜 골랐는지 조금만 묻고 → 다시 보여준다.

## 근거
- DesignPref: 전문 디자이너끼리도 선호 일치도 낮음(α=0.25). 개인화 선호 모델이 다수결보다 우수 → '최고의 디자인'이 아니라 '이 사람에게 맞는 디자인'.
- 웹페이지 매력은 약 50ms 노출로도 판단됨. 좋다/싫다는 빠르지만 '왜'는 별개 능력.
- 선택 과부하: 한 화면 후보는 3~5개.

## 인터뷰 설계
- 1~3문장 자유 입력 → 목적·대상 → 기억될 인상 3단어 + 피할 인상 → 콘텐츠 우선순위 → 시각 카드(좋아요/싫어요/상관없음) → 불확실한 축만 A/B → "제가 이해한 방향" 요약 확인 → 3안.
- 이미 확보한 정보는 다시 묻지 않는다. confidence ≤ 0.65이고 UI 영향이 큰 축만 질문.
- 스타일 이름을 묻지 말고 이미지+짧은 문구로 고르게 한 뒤 내부적으로 수치화.
- 모호한 형용사(깔끔, 고급, 힙, 감성, 따뜻, 전문적)는 즉시 변환하지 않고 대조 질문으로 분해. 예: "깔끔함"이 색 적음 / 정보 적음 / 정렬 일정 / 여백 많음 중 무엇인가.
- 싫어하는 것(anti-reference)은 반드시 수집. 강한 정보이자 hard constraint 후보.
- 말한 취향과 실제로 고른 취향을 분리 저장. 충돌 자체가 데이터.

## 충돌 우선순위
명시적 거부 > 추론 선호, 직접 고른 이미지 > 형용사 해석, 반복 신호 > 1회 단어, 실제 행동 > 자기평가, 접근성 > 미적 선호.
내부 우선순위: hard constraint → 접근성 → 1차 목표 → 핵심 콘텐츠 가시성 → 브랜드 가치 → 고른 시각 선호 → 형용사 → 성격 힌트 → 장식적 새로움.

## 3안
- Safe: 익숙한 IA + 개성 10~20% / Core: 추천 기본, 시그니처 결정 2~3개 / Stretch: 한 단계 실험적, 핵심 task 보존.
- 조합 요청("B 타이포 + A 색")은 고품질 신호.
- "정보구조는 안전하게, 자기표현은 1~3개의 시그니처 결정에서 대담하게."

## 금지
- 일대일 매핑 금지: 내향→검정, 개발자→monospace/터미널, 고급→검정+금색, 힙→네온, 감성→베이지.
- 인구통계·성격·문화 추정 금지. 저신뢰 추론은 질문으로 되돌린다.
- 유명 사이트(Apple 등) 외형 복제 금지. 요소 단위로만 참고.

## 지표 (베타)
질문 완료율, 3안 중 선택률, 첫 만족 preview까지 시간, publish 전환. 장기적으로 Manual Edit Distance(사용자가 무엇을 고쳤는지)가 가장 중요한 학습 신호.
