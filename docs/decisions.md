# 확정된 결정

## 서비스 범위
- 다른 사람들도 쓰는 서비스로 만든다(본인 포트폴리오 단일 사이트가 아님).
- 사용자가 만든 포트폴리오는 소유한 도메인의 1단계 서브도메인(`slug.도메인`)으로 제공한다.
- MVP에서 제외: 가격 정책, 바이럴 기능, Marketplace, Taste Twin, 커스텀 도메인 연결(베타 이후).
- 정적 HTML + JSON export는 서브도메인과 별개로 항상 제공한다("포트폴리오는 사용자의 것").

## 인프라
- 도메인은 이미 보유, DNS는 Cloudflare에서 관리.
- 도메인 하나로 시작한다: 루트 = 서비스 랜딩, `app.도메인` = 편집기·로그인, `*.도메인` = 사용자 사이트.
- 사용자 사이트는 반드시 1단계 서브도메인. 2단계(`a.sites.도메인`)는 Universal SSL이 커버하지 않는다.
- 라우팅: 와일드카드 DNS(`*`, A, 192.0.2.0, 프록시 켜짐) + Worker 라우트 `*.도메인/*` → Host에서 slug 추출 → R2 `sites/{slug}/...` 서빙. 라우트 패턴은 루트 도메인에 매칭되지 않는다.
- 편집기 Worker는 `app.도메인`에 Custom Domain으로 연결.
- 예약어: www, app, api, admin, mail, static, assets, help, support, status, blog, docs, dev, test.
- 슬러그: 영소문자·숫자·하이픈, 3~30자, 하이픈으로 시작·끝 불가.

## 도메인 하나 사용에 따른 보안 규칙
- 사용자 서브도메인과 `app.`은 브라우저에서 same-site로 취급되므로 SameSite 쿠키만으로는 CSRF를 막지 못한다.
- 인증 쿠키는 `__Host-` 접두사, Domain 속성 없이 발급(cookie tossing 방지).
- 상태 변경 API는 Origin 헤더가 정확히 `https://app.도메인`인지 검사 + CSRF 토큰.
- 사용자 사이트 CSP에서 script-src `'unsafe-inline'` 제거 예정(템플릿 JS는 별도 파일로).
- 장기 옵션: Public Suffix List 등록(베타 이후 검토).
- 운영: 신고 버튼, 사이트 비공개 처리(takedown), 계정당 생성 횟수 제한, 이용약관·개인정보처리방침, 만 14세 미만 법정대리인 동의.

## 프론트엔드
- 프론트엔드를 먼저 만들고 백엔드는 나중에.
- React + Vite. JavaScript + JSDoc(TypeScript 전환은 열려 있음).
- 배포 대상은 Cloudflare Workers 정적 에셋.
- MVP의 AI 부분은 규칙 기반 엔진 + 고정 목업 응답. Claude API 연결은 백엔드 단계.

## 3안 (2026-09-26, 사용자 위임으로 추천안 채택)
- 템플릿이 없는 grammar는 구조가 가장 가까운 구현 템플릿에 원래 grammar의 토큰을 입혀 보여주고, 그 사실을 안내 문구로 밝힌다. 템플릿은 자주 선택되는 순서로 추가.
- 배정: Core = 취향에 가장 가까운 grammar, Safe = 익숙함 55 이상 중 가장 가까운 것, Stretch = 표현력 +20·익숙함 −20으로 민 취향에 가장 가까운 것. 싫어한 grammar·hard 위반 grammar 제외.
- hard 제약(확인 단계에서 동의한 "피하고 싶은 인상")은 축 범위로 바꿔 후보를 거르고 토큰 조정 범위도 자른다(`src/data/avoidRules.js`). 사전에 없는 직접 입력 단어는 아직 적용 안 됨.
- 토큰은 grammar 기본 토큰 + 규칙 기반 조정(조정량 = 차이 × 확신도 × 안별 강도) + 대비 자동 보정. 실패 시 기본 토큰.
- 미리보기는 정적 HTML을 샌드박스 iframe(srcdoc)에 넣는다 — 발행 결과와 동일, 스크립트 불가, CSS·id 격리.
- 3안을 본 뒤: 고르기 + 좋았던 점(색·글자·배치·분위기·여백) + 섞기(색 묶음·글꼴 묶음만, 배치는 고른 안 그대로).
- "다시 만들기" 버튼 대신 인터뷰의 해당 단계로 돌아가 답을 고치게 한다.
- 미리보기용 이름·한 줄 소개는 3안 화면에서 선택 입력, 작업 목록은 예시(편집기에서 교체).

## 편집기·이미지·발행 (2026-09-27)
- 편집 범위: 콘텐츠(A) 먼저, 이어서 디자인 다듬기(B)까지. 디자인 편집은 edit 신호로 취향 학습에 쓴다.
- 이미지: 백엔드 전에는 브라우저에서 줄여(긴 변 1600px, WebP) IndexedDB에 저장. 백엔드 이후 R2 업로드로 교체.
- 가짜 publish: 점검 → 슬러그 → 연습 발행 → HTML·JSON 내려받기. 내려받기는 발행과 상관없이 항상 가능.

## 로그인 (2026-09-27) — 시작 시점은 아래 '가입 후 시작'으로 바뀜
- 이메일 6자리 코드(매직 링크 대신 — 메일을 연 앱·기기와 상관없이 입력 가능, 앱 안 브라우저에서도 동작). Workers + D1에 직접 구현.
- 로그인은 발행할 때만 요구. 그 전까지는 가입 없이 로컬에서.
- 메일 발송은 Resend(HTTP API). 로컬 개발은 발송 없이 로그 출력.
- 만 14세 미만은 보호자 이메일로 동의 요청, 동의 전 발행 불가. 한번 미만이라고 답하면 스스로 바꿀 수 없음.
- 카카오 로그인은 베타 이후 추가(이메일 계정과 연결 가능하게).

## 발행 (2026-09-27)
- 서버가 토큰 JSON + 템플릿으로 직접 렌더링(클라이언트 HTML 불신). 템플릿 코드는 앱과 서버가 같은 소스를 쓴다(Vite로 Worker용 번들 생성).
- 계정당 사이트 하나. 다른 주소로 발행하면 옮기고 예전 주소는 내린다. 비공개 전환 = 파일 삭제 + 주소 반환.
- 사용자 사이트 CSP: script-src 'none', img-src 'self', 폰트는 Google Fonts·jsDelivr(Pretendard)만. HTML은 no-cache(비공개·신고·동의 철회 즉시 반영), 이미지는 내용 해시 이름으로 영구 캐시.

## 동기화 (2026-09-27)
- 초안과 인터뷰 세션을 계정당 한 벌 서버에 둔다. 로그인은 선택("다른 기기에서도 이어 쓰기"), 만 14세 미만은 보호자 동의 뒤부터.
- 충돌은 버전(낙관적 잠금)으로 감지하고 조용히 덮어쓰지 않는다 — 사용자가 "다른 기기 내용 / 이 기기 내용" 중 고른다.

## Claude API (2026-09-26)
- Claude가 3안 전체(grammar 선택·토큰·근거 문장)를 만든다. 단 출력은 토큰 JSON뿐이고, 규칙 엔진이 안별로 다시 검사해 문제 있는 안(hard 제약 위반·형식 오류·대비 미달·수상한 문장)만 규칙 결과로 바꾼다. 시그니처·부가 안내는 실제 템플릿 기준 문구를 쓴다.
- 모델 Claude Opus 5.5(`claude-opus-5-5`), effort는 평가로 정한다(시작값 low — 사용자가 기다리는 화면이라). 안전 분류기 거절은 서버 대체 모델(`fallbacks: "default"`)로.
- 로그인 + 나이 확인(보호자 동의)이 끝난 계정만 Claude를 쓴다. 나머지는 규칙 엔진 — 만 14세 미만의 글이 동의 전에 외부로 나가지 않게.
- 프롬프트 인젝션 대비: 사용자 글은 `<taste_data>` 안 데이터로만, 이메일·전화번호·링크는 가려서 보내고, 구조화 출력(고정 스키마)으로만 받는다. 호출 기록엔 사용자 글·출력을 남기지 않는다.
- 비용 상한: 사용자별 시간당 10번, 서비스 전체 하루 300번(설정값). 넘거나 실패하면 조용히 규칙 결과.

## 가입 후 시작 (2026-09-26)
- "로그인은 발행할 때만"을 바꿔, 가입·로그인(무료)을 먼저 하고 시작한다. 방법은 그대로 이메일 6자리 코드(비밀번호 없음), 가입 직후 나이 확인.
- 이유: 인터뷰부터 계정에 저장(다른 기기·이어 쓰기), Claude 3안을 처음부터 쓸 수 있게(로그인·나이 확인한 계정만 쓰는 규칙과 맞물림).
- 만 14세 미만은 보호자 동의를 기다리는 동안 이 기기에서만 먼저 만들 수 있다.
- 로그아웃하면 이 기기의 작업을 지운다(공용 기기에서 다음 사람·다른 계정이 보지 않게). 서버에 없는 작업이면 먼저 경고.

## 블루펜슬 편집기 (2026-09-27)
- 첨부받은 블루펜슬(자유 HTML 편집기)을 그대로 넣지 않고 우리 구조로 옮긴다. 이유: 발행은 서버가 토큰·템플릿으로 다시 그리므로 HTML 수정은 사라지고, HTML을 받으면 "사이트는 템플릿·토큰으로만" 보안 규칙이 깨지고, 자유 수정은 어느 취향 축이 바뀌었는지 알 수 없어 학습 신호가 끊긴다. API 키도 브라우저에 노출되는 구조였다.
- 1단계: 개성 포인트는 개발자가 쓴 CSS의 허용 목록(id만 저장), 분위기 프리셋·글꼴은 대비 게이트·글꼴 허용 목록을 거친다. 2단계 미리보기 캔버스, 3단계 표시하기·대화(Claude는 내용·토큰·개성 포인트 변경만, 서버 경유).
- 사이트 CSP에 img-src data: 허용(그레인·커서 무늬). data: 이미지는 외부 요청이 없어 추적에 쓰일 수 없다.
- 3단계 다듬기: Claude 결과는 바로 적용하되 "모두 되돌리기"를 둔다(미리 확인 단계보다 빠르고, 되돌리기로 신뢰를 지킨다). 사용자 요청 문장 자체는 DNA에 저장하지 않는다(디자인 변경만 edit 신호로).
